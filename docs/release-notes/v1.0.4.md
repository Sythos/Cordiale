# Cordiale 1.0.4

This release adds E2E key requests, a public E2E master key view in Admin, and SAS verification for direct chats. It also fixes stale E2E data after a master key change or a session change.

Package version: `${PACKAGE_VERSION}`. Tag version: `${VERSION}`. GitHub Actions run: `${BUILD_ID}`. Attempt: `${BUILD_ATTEMPT}`.

## Choose one package for your system

* **Windows:** x64 or ARM64 installer and portable archive.
* **macOS:** Intel or Apple Silicon disk image and portable archive.
* **Linux:** Debian 13, Ubuntu 26.04, AlmaLinux 10, Arch Linux, or a portable archive. Linux packages are available for x86_64 and ARM64 where supported.
* **Source:** source archive.

The release includes SHA256 checksum files. The build workflow also creates provenance attestations. See the [installation guide](https://github.com/Sythos/Cordiale/blob/main/docs/installation.md) for package names, dependencies and install steps.

All packages are unsigned. Cordiale does not use a code-signing certificate. Windows SmartScreen and some Linux package managers can show a warning. This is expected for an unsigned community build. It does not mean that someone changed the package.

## Complete change summary

### New features

* The program starts an E2E key request when a new direct chat opens.
* The locked chat shows the state of the E2E key request.
* The Admin view shows the public E2E master key. You can copy the key.
* The program reads the public master key from the device certificate when the certificate has the key.
* The program has a read-only method for the public E2E master key.

### SAS verification

* The E2E engine creates a SAS code and has a confirm step.
* The locked query shows a SAS check banner.
* A verified contact can show the SAS code again.
* The documentation describes the SAS verification flow.

### Fixes

* The program drops cached peer devices and sessions after a master key change.
* The program clears the Admin E2E identity view after a session change.

### Documentation and tests

* The E2E contract describes the limit of the KEYREQ proof.
* New tests check the KEYREQ transport for the E2E send route.
* New tests check the key request for the query open paths.
* New tests check SAS reject, cancel, and lane separation in the UI handler.
* A dev dependency is added for the SAS handler tests.
