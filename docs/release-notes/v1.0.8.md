# Cordiale 1.0.8

This release adds encrypted actions and slash commands in E2E queries. It adds peer key verification, device activity, and an in-app pairing offer.

## Choose one package for your system

* **Windows:** x64 or ARM64 installer and portable archive.
* **macOS:** Intel or Apple Silicon disk image and portable archive.
* **Linux:** Debian 13, Ubuntu 26.04, AlmaLinux 10, Arch Linux, or a portable archive. Linux packages are available for x86_64 and ARM64 where supported.
* **Source:** source archive.

The release includes SHA256 checksum files. The build workflow also creates provenance attestations. See the [installation guide](https://github.com/Sythos/Cordiale/blob/main/docs/installation.md) for package names, dependencies and install steps.

All packages are unsigned. Cordiale does not use a code-signing certificate. Windows SmartScreen and some Linux package managers can show a warning. This is expected for an unsigned community build. It does not mean that someone changed the package.

## Complete change summary

### New features

* Users can run slash commands in encrypted queries.
* The /me command sends an encrypted action. Cordiale sends a CTCP ACTION to the locked peer as an encrypted action. The E2E engine shows received encrypted actions.
* Users can verify the key of a peer manually. The E2E chat has a peer key view and a verify action.
* The E2E view shows device activity. It also shows advice for identity recovery.
* The recovery advice uses the saved recovery reason when the E2E engine opens. The advice names the pairing roles.
* The /e2e forget step removes a replaced E2E identity.
* Protocol 55 adds an in-app pairing offer. It replaces the pairing link and the QR code.
* The pairing window picks the network from the sealed offer of the holder.
* An unpaired session can receive a pairing invite.

### Fixes

* The /query command with no nick closes the locked query.
* Cordiale keeps the manual pairing code while the rendezvous is open.
* A manual pairing clears the waiting invite.
* A network reset clears the provisioning marker.
* Cordiale resumes a pending server reset on forgotten networks when it reconnects.
* The peer key view closes when a trust alarm occurs.
* The key check keeps the SAS and trust alarm behavior.

### Documentation and tests

* A new plain-language guide explains encrypted chat. The guide says that lost-device revocation needs the master-key device.
* The E2E user guide describes slash commands, the forget step, device activity, and identity recovery.
* The documents describe the pairing invite contract, the receive rules, and the protocol 55 pairing offer.
* The documents describe the order of recovery reasons and the late choice of network.
* New tests cover the locked query close, the peer key check, and the pairing flow.
