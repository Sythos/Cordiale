# Cordiale 1.0.24

This release adds local notification sounds and an AAC fallback reader. It also fixes several session, reconnect and media bugs. It adds six interface translations in four languages.

Package version: `${PACKAGE_VERSION}`. Tag version: `${VERSION}`. GitHub Actions run: `${BUILD_ID}`. Attempt: `${BUILD_ATTEMPT}`.

## Choose one package for your system

* **Windows:** x64 or ARM64 installer and portable archive.
* **macOS:** Intel or Apple Silicon disk image and portable archive.
* **Linux:** Debian 13, Ubuntu 26.04, AlmaLinux 10, Arch Linux, or a portable archive. Linux packages are available for x86_64 and ARM64 where supported.
* **Source:** source archive.

The release includes SHA256 checksum files. The build workflow also creates provenance attestations. See the [installation guide](https://github.com/Sythos/Cordiale/blob/main/docs/installation.md) for package names, dependencies and install steps.

All packages are unsigned. Cordiale does not use a code-signing certificate. Windows SmartScreen and some Linux package managers can show a warning. This is expected for an unsigned community build. It does not mean that someone changed the package.

## Complete change summary

### New features

* Cordiale plays notification sounds for live mentions and direct messages.
* The notification sounds also work for buffered, action and encrypted direct messages.
* The local notification sound settings are added.
* Five public-domain notification sound files are added.
* The player has an AAC fallback reader, audio diagnostics and a viewer note.
* The player plays the first audio track that opens.
* The interface has six more translations in four languages.

### Fixes

* The WebM reader decodes laced frames. It accepts all-ones EBML lace sizes.
* The MP4 reader limits the sample mapping for malformed files.
* The WebSocket handshake has a deadline and shutdown handling.
* The client reconnects when a Phoenix heartbeat reply is missing.
* The client retries unconfirmed read-cursor updates after a failed POST.
* The client keeps one send task for each window. It flushes the cursors on reconnect.
* The client ignores stale media link probes after logout or a newer open.
* The client drops E2E file results after logout starts.
* The client ignores preference results from an earlier session.
* The personal preference Save action uses the loaded session.
* Each WHOIS avatar result is bound to its WHOIS view.
* Local settings changes use a locked update. This keeps the local settings during a server update.
* The window bounds stay valid when the user leaves full-screen mode on Windows.
* The audio peak uses a compare-and-swap loop.
* The sound mention check uses the nick of the line network.
* Encrypted direct message sounds use the locked window key.

### Tests

* The tests cover the stsc run sample size table.
* The tests cover the heartbeat reconnect.
* The tests check the translations of the interface texts.
* The tests cover the volume gain.
* The debounce test uses widths above the new minimum.

### Documentation

* The documentation describes the local notification sounds.
