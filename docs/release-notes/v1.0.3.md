# Cordiale 1.0.3

This release adds ignore actions, media viewer actions, and shared channels in a peer query. It also fixes problems in direct messages, admin data, radio playlists, and server address handling.

Package version: `${PACKAGE_VERSION}`. Tag version: `${VERSION}`. GitHub Actions run: `${BUILD_ID}`. Attempt: `${BUILD_ATTEMPT}`.

## Choose one package for your system

* **Windows:** x64 or ARM64 installer and portable archive.
* **macOS:** Intel or Apple Silicon disk image and portable archive.
* **Linux:** Debian 13, Ubuntu 26.04, AlmaLinux 10, Arch Linux, or a portable archive. Linux packages are available for x86_64 and ARM64 where supported.
* **Source:** source archive.

The release includes SHA256 checksum files. The build workflow also creates provenance attestations. See the [installation guide](https://github.com/Sythos/Cordiale/blob/main/docs/installation.md) for package names, dependencies and install steps.

All packages are unsigned. Cordiale does not use a code-signing certificate. Windows SmartScreen and some Linux package managers can show a warning. This is expected for an unsigned community build. It does not mean that someone changed the package.

## Complete change summary

### New features

* The nick context menus have Ignore and Unignore actions.
* The media viewer has Download and Share actions. The Share action has a link fallback choice.
* A peer query shows the shared channels. The shared channel buttons scroll.
* The program declares protocol 51. The documentation describes the admin credential restart.
* The admin UI reports the result of each credential restart.
* An older server can stop a credential session. In this case, the program shows neutral text.

### Direct messages and encryption

* After a reconnect, the program loads all missed direct message pages.
* The program splits multi-device E2E sends by the frame limit.
* The program refuses a send when one E2E body does not fit alone.
* The E2E contract describes the multi-device send rule.

### Fixes

* The program keeps saved aliases when the alias read fails.
* The program keeps admin data and shows an error when a refresh request fails.
* The `/beep` command shows success only after the program saves the sound setting.
* The program uses the network nickname for moderation permission checks.
* The program refreshes the moderation state after a change of your own nickname.
* The locked query peer stays in the shared channel refreshes.

### Security

* The program refuses server URLs that contain user information, a query, or a fragment.
* Test assertion messages do not print secret test URLs.

### Radio playlists

* The program limits the size, time, and parsing work for radio playlists.
* The program decodes playlist bodies with the charset and byte order mark.
* The program shows a clear reason when a radio playlist fails.

### Dependencies

* `tokio` is updated from 1.53.3 to 1.54.1.
* `taiki-e/install-action` is updated from 2.87.29 to 2.87.32.
